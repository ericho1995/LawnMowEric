# The Lawn Care

Online lawn mowing business — customer-facing site with an embedded quote
request form and a lightweight admin job queue. Domain: `thelawncare.com.au`
(registered; hosting not yet connected — see "Running it" below).

> Formerly branded "MowMate" — renamed after the `thelawncare.com.au` domain
> was purchased. See `CHANGELOG.md` [Unreleased] for the rename, and note
> that older changelog entries correctly refer to "MowMate" since that was
> the name at the time.

## Status

**Phase 1 (MVP)** — marketing site + working quote capture. See
[`docs/requirements.md`](docs/requirements.md) for the full requirements
doc, phased roadmap (Phase 2: pricing engine & payments, Phase 3: two-sided
contractor marketplace), and open decisions.

## Structure

**Edit `src/`, not the HTML at the repo root.** The root `.html` files and
`lawn-mowing/` are generated by the build (each starts with a `GENERATED`
comment) and are overwritten on every build.

```
src/site.config.mjs     prices, booking rules, GA id, backend URLs — start here
src/pages/*.html        page content (front matter at the top: title, description, …)
src/partials/           header + footer shared by every page
src/data/faqs.mjs       FAQs (shown on pages and emitted as FAQPage structured data)
src/data/suburbs.mjs    one entry per suburb -> lawn-mowing/<slug>.html
scripts/build.mjs       builds src/ into the root HTML files + sitemap.xml
scripts/check.mjs       post-build checks (links, anchors, titles, JSON-LD, …)
scripts/serve.mjs       local preview server
assets/css/site.css     the design system
assets/js/              site.js (menu, sticky bar), quote.js + booking.mjs
                        (quote form and day picker), estimator.js (map tool)
docs/apps-script/Code.gs  optional Google Sheets backend for leads + admin.html
docs/pre-live-checklist.md  what still needs doing before/after launch
tests/                  node --test suites (booking rules, build, Apps Script)
```

## Working on it

Needs Node 22 or newer, and nothing else — there are no npm dependencies.

```bash
npm run serve     # preview at http://localhost:8791 (and on your phone via the LAN address it prints)
npm run build     # regenerate the site after editing src/
npm run verify    # tests + build + checks — run before committing
```

Typical change: edit a file in `src/`, run `npm run build`, check it in the
preview, run `npm run verify`, commit both the source and the regenerated
HTML. The "Site checks" GitHub Action fails if the committed HTML doesn't
match the source, so a forgotten build gets caught.

`_config.yml` keeps `src/`, `scripts/`, `tests/` and `docs/` off the
public site — GitHub Pages only serves the built pages and `assets/`.

**Quote requests** try each configured route in turn (`assets/js/relays.mjs`):
the Apps Script backend (`gasWebhookUrl`), then Web3Forms
(`web3formsAccessKey`), then FormSubmit.co — all set in
`src/site.config.mjs`, the email relays forwarding to Eric's inbox. The
first one that confirms delivery wins; if none do, the customer gets a
pre-filled email draft and the address to copy, never a false
confirmation.

No Node on a machine? `scripts/serve.ps1` still previews the built site
(`powershell -ExecutionPolicy Bypass -File scripts/serve.ps1`), but you
need Node to rebuild after editing `src/`.

## Versioning

This repo follows [Semantic Versioning](https://semver.org/) via git tags
(`v0.1.0`, `v0.2.0`, ...) and [Keep a Changelog](https://keepachangelog.com/)
conventions in `CHANGELOG.md`. Bump the minor version for new sections/
features, patch for copy or styling fixes, major once the site is live in
production for real customers.
